When looking back to highlight one thing I learned in the readings, I can basically justify every fact within the first three chapters. Before learning about GitHub, I did not understand much. The purpose of commits, branches, and pull requests, were a foreign concept. I learned that commits create a history of changes, while branches allow you to make and test changes without immediately affecting the main version of the project. This is incredibly important when understanding the need for version control. Especially when multiple people are working on the same project at one time.
One challenge I faced began when I first opened up this GitHub assignment without completing the readings first. I realized that those were crucial to help me understand this new environment and how everything worked. Otherwise, I'd still be figuring out how to open a new branch. Through practice, I learned that I first need to make sure that I write my code within VS Code, save,  commit the changes with a message, then push to GitHub. I now understand and see how GitHub is extremely crucial in helping future team projects. Several people can work on different parts of an analysis using their own branches without interfering with eachother's work. This can make collaborations more seamless and easier to track changes to the code within a project.
